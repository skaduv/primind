# 问答回答中引用标记原样显示为 `[ref id="cN"]`

**缺陷类型**为 Primind 后端引用展开。**状态**为已修复并通过单元测试（后端在 Linux 容器内用 Go 1.26.0 运行，前端 `npm test` 与 `npm run type-check` 通过），改动保存在独立工作树分支 `dsh-af38551d-df9a`，尚未合并、未部署；带真实模型的手工验收（6.3 / AC5）还没有做。本文日期为北京时间（UTC+08:00）。

## 现象

在知识库「制度公示——综合管理」中，用快速问答模式、模型 `qwen3.8-27b-bf16` 提问：

> 车辆管理办法和中心停车场管理规定，对公司车辆的停放和使用要求是否一致？有没有相互冲突的地方？

页面顶部显示「检索完成 · 引用了2篇文档」，检索和引用登记正常。但正文里的引用没有变成引用卡片，而是原样显示为方括号文本，例如：

```text
……且交强险在有效期内[ref id="c2"]。
……购买交强险和商业保险且在有效期内[ref id="c9"]。
……并要求驾驶员严格遵守交通法规 [ref id="c15"] [ref id="c22"]。
```

同一段回答里每一处引用都是方括号写法，共出现 c2、c4、c8、c9、c11、c12、c15、c16、c17、c18、c22 等多个编号。

3 分钟后在同一知识库再问「长三角物理研究中心会议费综合定额标准具体是多少？」，回答引用了 4 篇文档，引用均正常显示为文档卡片，没有出现原样标记。

## 原因

1. 系统提示词要求模型用尖括号形式 `<ref id="cN"/>` 标注引用。[引用协议提示词](../../internal/modelcontext/citations.go#L22)
2. 模型输出后，后端用 `refTagRE` 匹配引用标签，再展开为前端可渲染的 `<kb .../>` 卡片。该正则只认尖括号：`(?i)<ref\s+id\s*=\s*"([^"]+)"\s*/?>`。[引用正则](../../internal/modelcontext/citations.go#L139) · [整段展开](../../internal/modelcontext/citations.go#L340)
3. 流式展开器 `citationStreamExpander.Feed` 只在遇到 `<` 时才缓冲、判断是否为标签。[流式展开](../../internal/modelcontext/citations.go#L388)
4. 这次模型把标签写成了方括号的 `[ref id="c2"]`。正则匹配不上，流式展开器也不拦截，文本原样下发到前端。

为什么同一模型下一次又正常（推断，未复现）：模型输出存在随机性。27B 本地模型遵守格式的能力弱于大模型，回答较长、引用较密时，容易「漂」成 Markdown 风格的方括号；同一段回答从头到尾都用方括号，说明是这次生成一开始就固定了写法，而不是个别失误。下一次生成按协议输出尖括号，所以正常展开。问题是间歇性的，不能因为一次正常就判断已经恢复。

## 回归验收

- 模型输出 `[ref id="cN"]` 或 `【ref id="cN"】` 时，页面显示为引用卡片，正文中不出现 `ref id=` 字样。
- 回答中正常的方括号内容（如 `[1]`、Markdown 链接）不受影响。
- 流式输出过程中不闪现半截的 `[ref id=` 文本。
