# 智能体共享时未提示保存模型配置

修复已在独立工作树分支 `dsh-ab1d0270-3bd7` 完成（2026-11-26），后端单元测试、前端测试和类型检查全部通过，**未合并、未部署**；在缺陷所在环境里的手工复测还没有做，复测前仍按下文"临时处理"操作。

用户在编辑窗口选好对话模型和 ReRank 后，可以直接切到「共享管理」提交。共享接口读取已保存的配置，模型选择待保存时，页面可能提示模型未配置，用户无法从提示判断需要先保存。

## 复现流程

用有权编辑自定义智能体的账号操作，目标共享空间的角色为编辑者或管理员。准备一个启用文档知识库检索、关联了可共享知识库的智能体。它已保存对话模型，已保存的 ReRank 模型为空。本空间有可选的 ReRank 模型。

1. 打开该智能体的「编辑」窗口，进入「模型配置」。
2. 在「ReRank 模型」下拉框选择一个模型，保留当前编辑窗口，跳过「保存并关闭」。
3. 在同一个编辑窗口切到「共享管理」，点击 `+`，选择目标共享空间，再点「共享」。
4. 页面提示模型配置不完整，本次共享失败。

## 实际结果

> Agent is not fully configured. Please set the chat model, and set the rerank model if the knowledge_search tool is enabled in agent settings.

现场核对的是「快速问答-中心制度」。原编辑窗口显示 `qwen3.8-27B` 和 `Qwen3-Reranker-4B`。在新标签页重新打开同一个智能体，对话模型仍显示 `qwen3.8-27B`，ReRank 一栏显示「请选择 ReRank 模型」。

## 原因

选择模型会更新编辑窗口内的 `formData.config`。点击「保存并关闭」才通过 `PUT /api/v1/agents/{id}` 写入模型 ID。[模型选择](../../frontend/src/views/agent/AgentEditorModal.vue#L554) · [保存实现](../../frontend/src/views/agent/AgentEditorModal.vue#L5047)

「共享」直接调用 `POST /api/v1/agents/{id}/shares`，提交目标空间和共享权限。后端重新读取智能体，发现对话模型 ID 为空，或启用知识库检索时 ReRank 模型 ID 为空，都会返回同一条提示。[共享提交](../../frontend/src/components/AgentShareSettings.vue#L235) · [共享校验](../../internal/application/service/agent_share.go#L194) · [报错文案](../../internal/handler/organization.go#L1405)

## 临时处理

在「模型配置」里确认选择后，点击「保存并关闭」。看到「智能体已更新」后，重新打开同一个智能体，确认 ReRank 仍显示所选模型，再从「共享管理」发起共享。

## 修改建议

1. 在共享提交前检测影响共享的未保存修改，至少覆盖对话模型和 ReRank 模型。可复用编辑器现有的表单快照机制。在 `AgentShareSettings` 发出共享请求之前拦截，保留当前选择，并明确提示「请先点击『保存并关闭』保存模型配置，再发起共享」。[编辑器表单快照](../../frontend/src/views/agent/AgentEditorModal.vue#L4156) · [未保存变更判断](../../frontend/src/composables/useModalShell.ts#L53)
2. 让后端区分缺少对话模型和缺少 ReRank 模型，前端提示具体缺项。用户打开已有的配置不完整的智能体时，可以直接从提示定位到「模型配置」里的对应字段。[模型校验分支](../../internal/application/service/agent_share.go#L211)

## 回归验收

- 已选 ReRank 且仍待保存时，点击「共享」会提示先保存，当前选择可见，本次操作发出的共享请求数为零。
- 已保存的模型原本齐全时，改选一个模型后直接共享，也会提示先保存。成功保存并重新打开后，两项模型与保存时一致，提交共享后目标空间出现在已共享列表。
- 已保存的对话模型为空时，提示缺少对话模型。知识库检索启用且已保存的 ReRank 为空时，提示缺少 ReRank。
- 知识库范围设为「不使用知识库」且已保存对话模型时，允许 ReRank 留空并通过共享的模型校验。

## 修复情况

分支 `dsh-ab1d0270-3bd7`（基线 `main@633ba77`），未合并。

- 编辑窗口里有未保存的修改时，点「共享」不再直接发请求：弹层里提示"模型配置等修改尚未保存，共享的是已保存的配置。"，按钮变成「保存并共享」和「取消」，当前选择保持不变。「保存并共享」先保存（窗口不关），保存成功后再共享，保存失败就停住。
- 后端的配置完整性检查收拢成 `CheckAgentReadiness`，共享被拒时在 `details.issues` 里说明缺的是对话模型还是 ReRank 模型（或模型已不可用），状态码和原文案不变。前端据此显示中文提示，「去设置」直接跳到「模型配置」里对应的字段。
- 已共享的智能体保存时如果配置变得不完整，会提示"该智能体已共享，当前配置会导致接收方无法使用"，不拦截保存；接收方的列表和选择器对这类智能体显示"配置不完整，请联系创建者"，不能选择。
